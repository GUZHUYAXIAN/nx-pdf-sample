# NX 制图批量 PDF 导出工具设计

- 日期：2026-08-26
- 状态：书面规格已获用户批准，可按批准的实施计划开发
- 项目目录：`E:\Codex\projects\nx-pdf-sample`
- 首个受支持环境：Windows 11 x64、Siemens NX 10.0.0.24

## 1. 背景与已验证事实

用户需要把多个 NX 制图 PRT 批量导出为 PDF。红框中被称为“图层”的对象实际是部件导航器中 `图纸 -> 图纸页` 下的 Drawing Sheet，而不是 1-256 普通 Layer。

当前机器已只读确认：

- NX 版本为 10.0.0.24，根目录为 `D:\Program Files\Siemens\NX 10.0`。
- `UGII\run_managed.exe`、`UGII\run_journal.exe` 和 NX Open .NET 程序集存在。
- NX 10 的 `PrintPDFBuilder` 支持选择多个 Drawing Sheet、生成 PDF 和追加页面。
- `DrawingSheet.GetDraftingViews()` 可作为有效制图页的确定性判据，仍须在当前样例上真机证明。
- 制图 PRT 依赖同目录模型才能正常解析制图视图。
- 参考 PDF 是 NX 生成的单页 A2、白底黑线、无水印文件。

私有样例包括一个制图 PRT、一个同目录关联模型和一份人工参考 PDF。三者位于 `samples/private/`，不属于 Git 内容。

## 2. 目标

构建一个 Windows x64 本地便携工具：

1. 批量选择或发现候选 PRT。
2. 用 NX 10 官方 NX Open 接口识别制图文件和有效 Drawing Sheet。
3. 跳过只有预制图框、标题栏、通用技术要求或预制表格的模板页。
4. 按 NX 10 公开 `DrawingSheets` 集合返回顺序，将有效页导出为一个同名多页 PDF。
5. 提供安全的已有 PDF 跳过或覆盖策略。
6. 在不修改源 PRT、模型、NX 或系统配置的前提下交付可核验结果。

## 3. 非目标

V1 不实现：

- STEP、DWG、DXF、CGM、3D PDF 或其他格式；
- Teamcenter、PDM、云端上传或远程服务；
- 文件夹后台监控、定时任务或自动发布；
- 多个 NX 进程并行导出；
- 图纸编辑、模型修复、视图重建或 PRT 保存；
- NX 12 或其他版本的兼容承诺；
- 安装程序、系统服务、注册表集成或自动更新；
- GitHub Release、远程推送或公开样例。

## 4. 用户工作流

### 4.1 输入模式

GUI 提供两个互斥模式：

1. **扫描文件夹**：选择一个目录，发现 `.prt`。默认只扫描当前层级；用户可主动勾选“包含子文件夹”。
2. **手动多选 PRT**：只处理用户选择的文件，适合新增图纸或少量重导。

输入层不依赖 `DWG_` 或其他命名前缀。纯模型 PRT由 Worker 依据 Drawing Sheet 实际内容识别并跳过。

### 4.2 输出模式

GUI 提供两个互斥模式：

1. **跟随源目录**：PDF 写入对应制图 PRT 所在目录，默认选项。
2. **统一输出目录**：所有 PDF 写入用户指定目录。

输出文件名保持完整基本名，只替换最后一个扩展名：

```text
PRIVATE_SAMPLE_A.prt
-> PRIVATE_SAMPLE_A.pdf
```

统一输出目录中出现两个相同目标文件名时，预检查将全部冲突项标为“输出名称冲突”并阻止执行，不允许依赖处理顺序覆盖。

### 4.3 已有 PDF

GUI 提供两个互斥选项：

- **跳过已有 PDF**：默认；不为该文件启动 NX 导出。
- **覆盖已有 PDF**：生成并验证临时 PDF 后再替换旧文件。

批量过程中不逐个弹窗询问。

## 5. 架构

采用双进程架构。

### 5.1 便携 WinForms GUI

- C#、.NET 10、Windows x64、self-contained 单文件发布。
- 不加载 NXOpen DLL。
- 负责 NX 检测、输入输出、预检查、任务编排、进度、取消、结果和日志入口。
- 目标电脑不要求安装 Python、Visual Studio 或系统级现代 .NET。

### 5.2 通用核心与协议

核心层不依赖 NX，负责：

- 扫描、递归开关、多选列表、去重和路径验证；
- 输出命名、已有文件策略和冲突检测；
- Job/Result 数据契约；
- Worker 启动、事件解析、取消与结果汇总；
- 中文错误映射和隐私安全日志。

跨进程任务目录包含 `job.json`、`result.json` 和本次运行日志。`result.json` 是权威完成记录，不能仅凭进程退出码宣称成功。

### 5.3 NX 10 Worker

- C#、.NET Framework 4.8、x64，引用当前 NX 10 `UGII\managed` 下的 NXOpen 程序集。
- Siemens DLL 设置为不复制，不进入发布包。
- 由已验证的 `UGII\run_managed.exe` 启动。
- 按任务顺序逐个处理 PRT，不并行。

目标 Windows 11 机器必须已有可用的 .NET Framework 4.8 系统组件；产品不负责安装、启用或修复它。用户不需要额外安装现代 .NET，GUI 的 .NET 10 运行时包含在自包含发布中。若 Worker 运行条件不满足，预检查应明确拒绝运行并报告原因。

.NET Framework 4.8 Worker 能否被当前 NX 10 入口加载是第一道真机门槛。如果失败，开发必须停止并提交证据，书面修订目标框架后才能继续；不得在没有证据时跨版本猜测或绕过 `run_managed.exe`。

## 6. Drawing Sheet 处理

对每个候选 PRT：

1. 通过 NX 打开文件并收集完整 PartLoadStatus。
2. 无 Drawing Sheet 时标记“纯模型，已跳过”。
3. 按 NX 内部图纸顺序枚举 Drawing Sheet。
4. 调用 `GetDraftingViews()`；至少有一个实际制图视图的页为有效页。
5. 没有制图视图的页无论是否含图框、标题栏、通用技术要求或预制表格，均视为模板页并跳过。
6. 有视图但关联模型缺失、视图加载失败或更新失败时，该 PRT 失败；不能降级成模板页。
7. 更新有效页中需要更新的制图视图。
8. 使用 `PrintPDFBuilder` 将有效页写入同一临时 PDF。
9. PDF 使用白色背景、黑色线条、每页原始图幅、无水印；不统一缩放。
10. 关闭 PRT，不调用任何保存接口。

V1 的唯一导出顺序契约是 NX 10 公开 NXOpen API 返回的
`workPart.DrawingSheets` 集合枚举顺序。Part/Drawing Navigator 的时间戳、依赖
等显示排序属于 NX GUI 偏好，不属于导出契约；本机 NX 10 没有找到可支持地读取
该可见树排序的公开 API。`UF_DRAW_ask_drawings` 只可用于诊断关联，不得覆盖公开
集合顺序。禁止按字母、自然名称、数字名称或不透明 Tag 值重新排序。

> 2026-08-29 经用户批准，本段替代原“可见导航器顺序”要求，用于解决
> NX 10 公开 API 与 GUI 时间戳显示排序之间不可支持的冲突。

## 7. 安全输出

### 7.1 跳过

目标 PDF 已存在且策略为跳过时：

- 保留原文件；
- 不启动该项的 NX 导出；
- 记录“已存在，已跳过”；
- 继续后续文件。

### 7.2 覆盖

覆盖流程：

1. 在目标目录创建唯一临时路径。
2. Worker 只向临时路径输出。
3. 验证 NX Commit 成功、文件存在、非零、PDF 文件头有效且页面数等于有效页数。
4. 页面验证由产品内的托管 `IPdfInspector` 实现，不依赖 Python或外部进程；实现选型须在实施计划中说明许可证和发布影响。
5. 验证通过后原子替换旧 PDF。
6. 替换失败时保留或恢复旧 PDF。
7. 清理临时文件并记录明确结果。

任何失败都不得留下被当作正式输出的残缺 PDF。

## 8. 源文件与系统保护

- Worker 不调用 PRT 保存、另存或写回接口。
- 打开前后核对源 PRT 的长度和最后修改时间。
- 真机验收对制图 PRT和关联模型执行导出前后 SHA-256 比对。
- 任何源文件变化都是严重失败。
- 缺失依赖和故障测试只在临时副本上进行。
- 不修改 NX 安装、NX 配置、PATH、注册表、服务或全局环境变量。
- 产品运行时不联网、不下载、不安装、不更新。

## 9. 失败、继续和取消

- 每个 PRT 有独立结果。
- 单文件失败后继续后续文件。
- 结构化状态至少包括：成功、覆盖、已有跳过、纯模型、无有效页、名称冲突、取消、失败。
- 用户取消后完成当前不可中断原子操作，在下一文件开始前停止。
- GUI 关闭时不能粗暴终止正在替换 PDF 的 Worker；应进入安全停止流程。
- 所有异常必须进入日志和用户结果，不允许空 catch 或吞异常。

## 10. GUI

单窗口包含：

1. NX 版本、根目录和验证状态。
2. 输入模式、文件夹/文件选择及递归开关。
3. 输出模式及统一输出目录。
4. 已有 PDF 的跳过/覆盖选择。
5. 预检查列表和问题提示。
6. 开始、取消、当前文件和整体进度。
7. 逐文件结果、汇总、打开输出目录和打开日志。

不适用于当前模式的控件隐藏或禁用。V1 不提供复杂颜色、线宽、水印、纸张缩放或打印机设置。

## 12. 测试策略

### 12.1 自动化测试

覆盖：

- 当前目录/递归扫描和手动多选；
- 去重、缺失路径、中文、空格、多点号和扩展名大小写；
- 同名 PDF、输出目录和统一目录冲突；
- Job/Result 往返、状态汇总和取消；
- 有视图页保留、无视图模板页跳过；
- 输入顺序保持不变；
- 临时输出、验证、替换和恢复逻辑；
- 日志脱敏和用户错误映射。

确定性逻辑采用测试先行；NX 对象通过窄接口与纯数据事实隔离，不能用假对象代替真机门槛。

### 12.2 真机门槛 1：Worker 启动

证明：

- NX 文件与 DLL 真实存在；
- `run_managed.exe` 能加载 Worker；
- Worker 能取得真实 Session 和 UFSession；
- 参数、当前目录、标准输出和退出码可靠。

失败则停止后续实现。

### 12.3 真机门槛 2：当前样例

1. 记录制图 PRT和模型的导出前 SHA-256。
2. 输出全部页、有效页和模板页清单及理由。
3. 证明有效页顺序与公开 `DrawingSheets` 集合返回顺序一致。
4. 生成同名多页 PDF。
5. 验证 PDF 页数和每页纸张尺寸。
6. 渲染全部页面并检查。
7. 将 A2 页与人工参考 PDF 对照。
8. 再次计算两个 PRT 的 SHA-256，必须完全一致。

不得预设样例只有 A2 一个有效页。

### 12.4 真机门槛 3：批量行为

验证两种输入、递归开关、两种输出、跳过、安全覆盖、纯模型跳过、缺失依赖失败、同名冲突、单文件失败继续和安全取消。
