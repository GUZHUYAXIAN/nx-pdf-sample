# NX 制图批量 PDF 导出工具 V2 设计

- 日期：2026-09-08
- 状态：设计内容已获用户逐节批准，等待书面规格复核
- 项目目录：`E:\Codex\projects\nx-pdf-sample`
- 目标版本：`v2.0.0`
- 支持环境：Windows 11 x64、Siemens NX 10.0.0.24

## 1. 背景

V1 将 NX 根目录固定为开发机上的
`D:\Program Files\Siemens\NX 10.0`。同事电脑安装了相同的 Siemens NX
10.0.0.24，但安装目录不同，导致发布版无法通过环境检测和启动 Worker。

V1 另有两项明确延期到后续大版本的机器配置 QA：

- GitHub Issue #2：100%、125%、150% DPI 下的 GUI 视觉验收；
- GitHub Issue #3：干净解压后的物理断网实机验收。

V2 将安装路径适配、DPI 布局与视觉验收、物理断网验收作为同一个版本的三个
工作包处理。Issue #2 和 Issue #3 在对应证据完整前继续保持未验证状态。

## 2. 目标

1. 在不依赖开发机盘符和安装目录的情况下发现 Siemens NX 10.0.0.24。
2. 自动发现失败或存在歧义时允许用户手动选择 NX 根目录。
3. 只保存经过统一验证的 NX 根目录，并在保存路径失效时安全回退到重新发现。
4. 保持 V1 的双进程、顺序处理、安全输出和源文件保护契约不变。
5. 修复已知的固定坐标 DPI 风险，并完成 100%、125%、150% 人工视觉验收。
6. 完成干净解压后的物理断网真实导出验收。
7. 在同事电脑上证明非开发机路径可被发现并用于真实 Worker 启动和导出。
8. 提供可直接交给同事 Codex 的验证提示词和给同事本人的操作清单。

## 3. 非目标

V2 不实现：

- NX 10.0.0.24 以外的版本支持；
- NX 12、NX 2206 等其他目录结构兼容；
- 修改、修复或重新安装 NX；
- 写入注册表、系统或用户环境变量、PATH、服务或 NX 配置；
- 全盘无界扫描、网络发现、远程配置或自动下载；
- GUI 与 Worker 合并、GUI 直接加载 NXOpen，或并行启动多个 NX 会话；
- 安装程序、自动更新、遥测或联网服务；
- 自动操作 Windows/NX GUI、自动切换显示缩放或自动截图；
- 未经用户单独授权的推送、标签、GitHub Release 或公开发布。

## 4. 保持不变的 V1 契约

- GUI 继续使用 .NET 10 Windows x64 自包含发布，不加载 Siemens 程序集。
- Worker 继续使用 .NET Framework 4.8 x64，并只通过已验证安装中的
  `UGII\run_managed.exe` 启动。
- NXOpen 与 NXOpen.UF DLL 不复制进发布包。
- PRT 串行处理，不并行运行 NX 会话。
- Drawing Sheet 的有效性、顺序和导出规则不变。
- 安全覆盖必须在新临时 PDF 通过验证后才替换旧 PDF。
- 不调用 NX 保存接口，不修改源 PRT 或关联模型。
- 产品运行时离线，不安装、下载或联系外部服务。

## 5. NX 安装发现架构

### 5.1 组件边界

NX 安装发现从现有窗体和单一路径检测器中拆分为以下职责：

- `NxInstallationCandidate`：保存候选根目录及其一个或多个来源；
- `INxInstallationCandidateSource`：只负责读取一类候选，不判断是否受支持；
- `NxInstallationValidator`：标准化路径并执行唯一的文件与版本验证；
- `NxInstallationDiscoveryService`：按顺序收集、验证、去重和选择候选；
- `NxSettingsStore`：只保存最近一次经过验证的根目录；
- `ApplicationController`：编排检测状态、用户选择和 Worker 启动；
- `MainForm`：展示状态、候选和错误，不承载发现规则。

相邻的 `nx-step-launcher` 只能作为只读设计和测试模式参考；V2 不复制其 STEP
Translator 或 Java 检测功能，也不修改该项目。

### 5.2 有界候选来源与顺序

生产装配按以下顺序收集候选：

1. `%LocalAppData%\NxDrawingPdfExporter\settings.json` 中保存的有效路径；
2. 64 位和 32 位注册表视图中的 Siemens/Unigraphics NX 键；
3. Windows 已安装程序项中 Siemens NX 10.0 的 `InstallLocation`；
4. 当前进程的 `UGII_BASE_DIR` 和 `UGII_ROOT_DIR`；

2026-09-10 修订：用户授权实施代理解决候选来源与发布审计的冲突后，删除 V1
历史默认路径候选。产品不内置任何开发机安装根目录；缺少上述来源时使用手动
选择兜底。手动选择仍经过统一精确版本验证，可保存供下次启动重新验证。

注册表与环境变量只读。任一候选来源读取失败时，记录脱敏诊断并继续其他来源；
单一来源失败不能让整个检测崩溃。V2 不遍历所有固定磁盘，也不解析快捷方式，
因为已批准流程含手动选择兜底，这两类广泛扫描不值得增加启动耗时和误报面。

若 `UGII_ROOT_DIR` 指向末级 `UGII` 目录，候选来源先转换成其父级 NX 根目录。
候选路径去除首尾空白、引号和末尾目录分隔符，转换为绝对路径后按 Windows
不区分大小写语义去重；同一路径的多个来源合并保留。

### 5.3 统一验证

自动发现、已保存路径和手动选择必须调用同一个验证器。一个候选只有同时满足
下列条件才有效：

1. 根目录存在；
2. `UGII\run_managed.exe` 存在；
3. `UGII\managed\NXOpen.dll` 存在；
4. `NXOpen.dll` 的文件版本可读且严格等于 `10.0.0.24`。

目录名称、注册表显示版本和环境变量名称只能提供候选，不能替代 DLL 文件版本
验证。路径无效、文件缺失、权限不足、版本不可读或版本不匹配均返回稳定的中文
用户消息和不含敏感数据的技术诊断。

验证结果包含根目录、`run_managed.exe` 完整路径、检测版本和候选来源。
`WorkerProcessLauncher` 只接收该验证结果中的启动器路径，不能使用编译期常量、
开发机路径或静默回退路径。

### 5.4 选择规则

- 只有一个有效候选时自动选择。
- 有多个有效候选且已保存路径仍有效时，自动选择该保存路径。
- 有多个有效候选且没有有效保存路径时，不自动猜测；要求用户选择。
- 没有有效候选时显示汇总原因并允许手动选择或重新检测。
- 手动验证失败时保留当前有效选择，不保存错误路径。
- 当前有效选择失效时，禁止开始新导出并重新运行发现流程。

检测、重新检测或切换选择期间，“开始导出”保持禁用。已经开始的批次继续绑定
启动时捕获的不可变验证结果，不在运行中切换 NX 路径。

## 6. 配置保存

配置路径为：

```text
%LocalAppData%\NxDrawingPdfExporter\settings.json
```

初始 schema 只保存 `schemaVersion` 和 `nxRootDirectory`。保存前必须确认路径来自
成功验证结果。写入采用同目录唯一临时文件、刷写完成后原子替换；失败时保留旧
配置并向用户显示可操作的错误，不影响当前内存中的有效选择。

配置不存在、为空、JSON 损坏、schema 不受支持或保存路径失效时，不崩溃、
不信任其值，继续其他候选来源。新有效路径选择成功后覆盖旧保存值。配置与日志
不得包含注册表全集、环境变量全集、许可证内容、源 PRT 路径或其他无关隐私。

## 7. GUI 设计

### 7.1 NX 环境区

现有单行 NX 状态区域改为自适应布局，包含：

- 状态文字：“正在检测”“已就绪”“需要选择”或“不可用”；
- 当前候选根目录与检测版本；
- 仅在存在多个有效候选时显示的候选下拉框；
- “重新检测”按钮；
- “手动选择 NX 目录”按钮。

自动发现唯一有效候选时直接进入“已就绪”。多个候选没有已保存匹配时，用户
确认选择后才进入“已就绪”。没有候选时明确引导用户选择包含 `UGII` 文件夹的
NX 根目录。手动选择仍执行完整验证，失败原因显示在环境区，不使用通用“未知
错误”代替具体原因。

### 7.2 DPI 安全布局

当前输入、输出、文件列表、按钮、进度和结果区域中依赖固定 `Left`、`Top`、
`Width`、`Height` 的布局改为嵌套 `TableLayoutPanel` 或 `FlowLayoutPanel`：

- 文本框、列表和进度控件随可用宽度伸缩；
- 按钮和标签使用 `AutoSize`，长状态文本允许换行；
- 主窗口具有合理最小尺寸，内容超出时可滚动；
- 长路径允许横向滚动、截断显示或工具提示查看完整值；
- 保留 `AutoScaleMode.Dpi` 和现有中文 UI 字体，不为各 DPI 写死独立像素尺寸；
- 设置从 NX 环境区到输入、输出、预检查和运行区的确定性 Tab 顺序；
- 检测期间、无有效 NX、运行期间和取消阶段具有明确且一致的禁用状态。

布局修改以消除现有固定坐标风险为限，不重新设计产品视觉风格或增加无关功能。

## 8. 错误处理与日志

安装发现错误分为候选来源错误与候选验证错误。来源错误不中断其他来源；验证
错误与对应候选关联。GUI 默认展示简短中文说明，日志保存错误代码、来源类型、
异常类型和必要的脱敏路径信息。

日志不得写入：

- 注册表或环境变量全集；
- NX 许可证内容；
- 用户凭据、令牌或密钥；
- 私有 PRT 的文件名、完整业务路径或图纸内容；
- 与检测无关的安装项。

没有有效 NX 时禁止创建 Job 或启动 Worker。Worker 启动仍以结构化 `result.json`
和输出文件验证为权威，不能仅凭 `run_managed.exe` 退出码报告成功。

## 9. 自动化测试

确定性逻辑继续采用测试先行。至少覆盖：

### 9.1 候选来源

- 已保存路径优先；
- 注册表 32/64 位视图及已安装程序位置；
- `UGII_BASE_DIR` 和指向 `UGII` 的 `UGII_ROOT_DIR`；
- 没有安装来源信号时不凭空生成默认路径候选；
- 单一来源抛异常后继续其他来源；
- 不读取或写入候选范围外的注册表与环境设置。

### 9.2 路径与版本验证

- 任意盘符、空格、中文、长目录名、尾部分隔符和大小写差异；
- 缺少根目录、启动器或 NXOpen DLL；
- 文件版本不可读、不是 `10.0.0.24` 或精确匹配；
- 多来源同一路径的去重与来源合并；
- 自动与手动路径走同一验证规则。

### 9.3 选择与配置

- 单候选自动选择；
- 多候选使用有效保存路径；
- 多候选无保存匹配时要求选择；
- 保存路径失效后重新发现；
- 错误手选不覆盖当前有效选择或配置；
- 配置首次创建、原子更新、损坏 JSON、未知 schema、写入失败和旧值保留。

### 9.4 控制器与 Worker 边界

- 检测中、无有效选择和多候选待选择时禁止导出；
- 选择成功后使用对应 `run_managed.exe`；
- 运行期间重新检测和切换路径受控；
- 任何路径都不静默回退到 V1 开发机常量；
- V1 输入、输出、取消、安全发布和结果汇总测试全部无回归。

## 10. 人工 DPI 验收（Issue #2）

电脑操作、显示缩放和截图必须由用户或同事本人完成；Codex 只提供步骤、预期
结果、截图矩阵和停止条件。

在最终候选包上分别以 Windows 100%、125%、150% 缩放启动程序。每档至少覆盖：

1. 完整主窗口和 NX 自动检测成功状态；
2. 多候选选择或可控测试状态，以及手动选择入口；
3. 扫描文件夹模式；
4. 手动多选 PRT 模式；
5. 统一输出目录与长路径；
6. 预检查列表；
7. 运行进度、结果列表和禁用状态。

每档截图必须包含 Windows 缩放设置证据和完整应用窗口。检查中文截断、控件重叠、
按钮裁切、不可访问区域、列表尺寸、长路径显示、Tab 顺序和状态切换。任一档出现
问题即停止验收、记录触发状态并返回代码修复；不得把存在明显缺陷的截图登记为
通过证据。

## 11. 物理断网验收（Issue #3）

静态网络 API 扫描、离线构建和 `--no-restore` 是辅助证据，不能替代物理断网
运行。最终候选 ZIP 必须解压到仓库外的新目录，并由用户或同事本人：

1. 记录制图 PRT 和关联模型的导出前 SHA-256；
2. 关闭 Wi-Fi、断开网线或禁用当前网络适配器；
3. 启动干净解压的 GUI，确认 NX 检测成功；
4. 完成一次受控真实导出；
5. 检查 PDF 页数、图幅、可视内容和日志；
6. 确认没有联网、下载、更新或认证提示；
7. 记录两个源文件的导出后 SHA-256，并要求逐项相等；
8. 保存证据后恢复网络。

任何源文件变化、网络访问提示、NX 检测失败、Worker 启动路径错误或正式输出残缺
均为硬失败。异常时保留日志和输出证据，停止重复运行，不修改 NX 或系统配置来
规避失败。

## 12. 同事电脑异路径验收

同事电脑安装相同的 NX 10.0.0.24，但实际根目录当前未知。V2 发布前必须在该机器
完成一次候选包验证，证明：

1. 非开发机固定路径的 NX 被自动发现；
2. 显示的 NXOpen 文件版本为 `10.0.0.24`；
3. Worker 使用该候选内的 `UGII\run_managed.exe`；
4. 干净解压后完成一次真实 PDF 导出；
5. 源制图 PRT 与关联模型前后 SHA-256 相等；
6. 日志没有开发机路径、私人文件名或无关系统信息。

若自动发现失败，记录各有界来源的脱敏诊断，再用“手动选择 NX 目录”验证兜底。
手动成功只能证明兜底有效，不能把“自动发现异路径”标记为通过；自动发现失败
必须先修复或明确保留为限制。

交付物包含：

- 一份给同事 Codex 的复制即用提示词，负责只读检查、命令验证、日志整理、哈希
  比较和脱敏报告；
- 一份给同事本人的 GUI、DPI、断网与截图操作清单；
- 明确的预期结果、截图范围、证据文件和异常停止条件。

同事 Codex 不得安装依赖、修改 NX、注册表、环境变量、PATH、服务、源 PRT 或
关联模型，也不得推送、打标签或发布。GUI 操作和截图由同事本人执行。
