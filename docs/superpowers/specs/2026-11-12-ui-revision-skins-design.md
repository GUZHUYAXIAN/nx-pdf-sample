## 1. 意图与约束

让工具成为外观协调、信息清楚的桌面应用。预检查成为主工作区，完整文件名、处理原因和最终版次易于识别。外观是重要目标，同时保留导出安全、可读性、键盘操作与既有 NX 能力。

必须保留：

- Windows 11 x64；便携 .NET 10 WinForms GUI，不直接加载 NXOpen。
- 两个独立 net48 x64 Worker：NX 10 使用 `UGII/run_managed.exe`；NX 2506 使用 `NXBIN/run_dotnet_nxopen.exe`。沿用 v2.0.1 已验证的精确组件元组，不扩展版本承诺。
- PRT 和 NX 会话串行处理；图纸有效页判断、公开 DrawingSheets 集合顺序、视图更新、取消和源文件保护规则不变。
- 不调用 PRT 保存接口；不改源 PRT、模型、NX 安装或系统配置。
- 运行时完全离线，不下载素材、不调用 AI、不安装依赖、不更新或遥测。
- 使用既有 SDK、包缓存和工具。新增依赖、安装、系统配置变更、推送和发布均不在本次授权内。
- 私有 PRT/PDF、截图、渲染页、日志与 Siemens DLL 不提交。真实 NX 验证前后逐次记录制图及关联模型 SHA-256。
- 保留历史人工验收限制；GUI 操作、DPI 切换、截图和物理断网按现有项目规则由用户执行，助手准备步骤和核对证据。

本文明确扩展旧规格中的三项要求：输出模式增加按源目录分组后的自定义目标；已有 PDF 策略增加升版；升版时在完整源基本名之后追加 `-R数字`。未涉及的安全边界不变。外层 checkout 保留 V1，后续只在活动 V2 工作树内实施。

## 2. 方案比较与选择

| 方案 | 表现与工程方式 | 取舍 |
|---|---|---|
| A：整体改版，部分控件自绘 | WinForms 标准表格负责编辑、选择、滚动和键盘；菜单、按钮、背景、卡片与配色统一；局部自绘支持视觉层次与皮肤 | 改造边界可控，保留成熟交互，同时完成全部已确认功能 |
| B：深度自绘界面 | 表格、行、编辑器和滚动条均参与复杂透明背景合成 | 能进一步追求背景透过表格的效果，但编辑、焦点、DPI 和维护负担更大 |

用户明确选择 A。不得迁移到 WPF、WebView、Electron，或将整张可编辑表格改成手绘画布。透明度作用于图片与背景效果，文字、编辑器和关键状态保持清晰；不实现整窗透出桌面的透明度或真实桌面玻璃效果。

## 3. 主窗口和表格

### 3.1 布局

菜单栏在顶部。NX 环境、输入、输出和已有 PDF 策略组成可收起的设置区；其下为预检查与结果区；底部保留开始、取消、当前任务和总体进度。

- 预检查与结果之间提供明显可拖动的水平分隔条，拖动改变两区高度。
- 设置区收起后仍能看到当前 NX、输入数量和输出方式摘要。
- 按可用空间设置最小高度，不能把操作按钮拖出可访问区域；小窗口由设置区/表格内部滚动承接内容。
- 记住窗口尺寸、分隔比例和列宽；恢复时限制在当前屏幕工作区与最小尺寸内。
- “恢复默认布局”只恢复布局，不清空文件、目录映射、版次或主题。

### 3.2 列与信息展示

预检查列顺序为：`序号 | 目录组 | 源 PRT | 目标 PDF | 状态 | 版次`。版次列只在升版策略下显示和编辑，其他列只读。手动输入清单至少包含序号、目录组和 PRT 文件名。运行结果延续序号、组标识和名称显示规则。

- 序号按当前任务发现/添加顺序连续编号；筛选不重新编号，不改变执行顺序。
- 源 PRT 与目标 PDF 显示完整文件名，不显示长目录前缀；路径保存在行模型中。
- 文件名列可拖宽，过长时自动换行，必要时提供水平滚动；不得用省略号替代完整名称。
- 状态、序号和版次列优先保持可读；文件名列共同分配剩余宽度。
- 悬停文件名单元格显示完整路径。悬停状态显示具体原因、规则及必要的冲突对象，不只重复状态名。
- 双击非版次单元格或按详情快捷入口，打开工具内的详情；双击版次单元格进入编辑，不打开详情。
- 详情包含源/目标完整路径、目录组、当前操作、两处发现的最高版次、自动建议、手动指定值、原因及运行后结果；可复制路径和打开所在文件夹。不自动启动 NX 打开 PRT。
- 搜索按文件名匹配；可筛选冲突/错误/失败。筛选只改变可见项，不默默改变任务范围，界面显示可见数与总数。

### 3.3 手动清单的折叠

扫描模式初始折叠手动清单；切到手动模式自动展开；返回扫描模式自动折叠。独立箭头允许在扫描模式展开查看。展开与选择输入模式独立，折叠不清空文件。扫描模式下手动清单只读，避免看似已加入本次任务；切回手动后可编辑。去重保留首次添加顺序。

## 4. 目录分组与输出映射

### 4.1 分组身份与标记

- 对实际候选 PRT 的完整父目录规范化，按现有 Windows 不区分大小写语义分组；不能只按末级文件夹名分组。
- 同源目录合并为一个组，按首次出现分配 A、B、…、Z、AA 等标识。
- 每组在 PRT 行和输出设置行使用相同的浅色底纹，同时显示组标识；选中、高对比度和深色主题仍保留文字标识或色条，不能只靠颜色。
- 颜色只表达目录归属。处理状态另用文字与小图标，不把目录颜色变成成功/失败含义。
- 同一会话内保留已有组的标识与配色；增加新组不改变现有组身份。不为分组改变文件执行顺序。
- 文件夹递归扫描同样按每个 PRT 的实际父目录分组。

### 4.2 两种互斥模式

一行显示：`分组输出（默认跟随 PRT 目录）`、`统一输出目录`，默认分组输出。

分组输出每组一行：组标识、来源摘要/文件数、目标目录、浏览、恢复源目录。

- 初始目标等于该组源目录；修改后显示“自定义”。路径允许直接输入并校验，浏览确认仅修改该组。
- 浏览取消不改变任何值；浏览不会切换输出模式。
- 多个组可以指向同一个目标目录，但保留各组映射和颜色，不合并来源身份。
- 无候选时显示“选择或扫描 PRT 后显示输出目录”，不凭空把扫描根目录当作所有递归文件的目标。
- 统一输出仅显示一条中性色目录行。切回分组恢复本会话的组映射；切到统一也不删除它们。
- 目标目录必须为可用绝对目录；不存在、不可读取、无效字符或过长路径等明确报告，不把读取失败解释为无历史文件。浏览器由用户创建的目录可以选择。
- 只读预检查不通过写文件宣称权限已验证；运行时实际写入失败仍报告具体错误。

## 5. 预检查的含义、编辑和失效

预检查只执行候选收集、目录映射、版本文件枚举、命名、冲突和状态推导，不打开 NX，不检查 PRT 内部制图视图。

“待导出”的说明必须表达：路径和输出规则检查通过，图纸内容将在导出时检查。不能显示“图纸已验证”。其他典型状态为：已有文件，跳过；待新增；将覆盖；输出名称冲突；版次无效；无法读取目录；需要重新检查。

预检查模型是实际运行的来源：

- 每条以规范化源路径作为身份，保存自动/手动版次来源、已解析的目标路径、发布意图和发现依据。
- 单元格接受编辑后，目标文件名与状态同步刷新。版次格式错误时就地说明，不提交错误值。
- 刷新预检查保留仍在任务中的手动版次，自动项重新计算；“恢复推荐版次”清除选中项的手动标记。
- 改输入、递归、输出目录或策略后使受影响的计划失效；保留相关手动值，重新校验后才允许执行。
- 更换语言、主题、列宽、分隔条、展开状态或筛选不使计划失效，不丢失选择或编辑。
- 开始时提交当前正在编辑的单元格，复核文件事实，然后冻结任务快照；不能丢弃手动值重新调用旧规划逻辑。
- 批量设置版次只作用于明确选中的行；隐藏行不因筛选被意外选中。每行独立重新校验目标。
- 本会话完成一次运行后仍保留手动版次，便于同版重导；再次运行前重新检查。重启应用不恢复业务文件/目录映射/手动版次。

## 6. 已有 PDF 与升版

### 6.1 三个策略

1. 跳过已有原名 PDF（默认）：保持原行为，只以 `完整基本名.pdf` 为目标。
2. 安全覆盖原名 PDF：保持原行为，不自动寻找并覆盖最高 R 版。
3. 升版（可指定版次）：按本节识别历史和建议版次，允许指定旧版或不连续新版本。

原名策略的含义在悬停中说明。切换出升版时隐藏版次列，但本会话手动值可保留供切回使用；不影响原名策略的目标。

### 6.2 命名和数字规则

`支架.prt` 的 0 版是 `支架.pdf`，1 版为 `支架-R1.pdf`，100 版为 `支架-R100.pdf`。不写 `-R0`。源 PRT 的完整基本名保留，不剥离图号、多点号或源名自身已有的 `-R2`：`组件-R2.prt` 的 1 版是 `组件-R2-R1.pdf`。

- 编辑接受十进制数字或大小写 R 前缀，例如 `2`、`R2`、`r100`；去除首尾空白并规范化显示。允许 0、R0，均映射原名。
- 拒绝负数、小数、混入路径分隔符、空值和其他文本；单元格有错误时禁止开始。
- 设计者选定的边界：使用非负 32 位整数，范围 0–2147483647；最高值不能再自动加一，明确报告并允许手动改为有效值，不溢出回零。R100 必须通过。
- 输出始终规范化为大写 R、无前导零。读取历史时识别大小写扩展名/R；发现 `-R0`、`-R02` 等非规范别名时列入原因并阻止该项升版，避免产生同一数值的两个名字；不自动改名或删除现有文件。该条是设计者对未讨论边界的保守处理。
- 临时、备份、相似前缀、其他扩展名不参与版本识别。必须精确锚定完整源基本名与末尾版次，不使用不加转义的通配匹配。

### 6.3 查找范围和推荐

仅查该 PRT 的源目录及本次实际目标目录的直接子文件，两处相同则去重。按该完整基本名的原版/R 版家族取数值最大值；不全盘或递归查历史，不看文件修改时间。

- 两处都没有该家族：推荐 0。
- 至少有原版或某个 R 版：推荐最大版次 + 1，不填补缺号。
- 源目录 R2、空目标：R3。
- 源目录 R2、目标目录 R5：R6。
- 源目录 R100、目标目录 R3：R101。
- 输入 R2 而实际目标目录的 R2 存在：将覆盖 R2；只在源目录存在、目标目录不存在时，在目标目录新增 R2，不改源目录里的 PDF。
- 输入 0：原名，是否覆盖由实际目标路径决定。

悬停/详情分别列出两处最高版次、建议值和手动值；版本历史只代表文件名序号，不宣称 PDF 内容一定更新或已经校验。

### 6.4 冲突与运行时变化

- 两个不同源 PRT 映射到同一目标路径，预检查阻止开始。
- 即使选择不同版次，两个不同源路径若在同一目标目录共享完整基本名，也按图纸家族归属不明阻止开始；不能用分配 R1/R2 混入同一家族来隐藏不同图纸的冲突。可调整组目标目录消除。
- 本批已知的不同基本名也可能交叠：`A.prt` 与 `A-R1.prt` 的 `A-R1.pdf` 既可能是前者 R1，也可能是后者原版。其版本查找范围或目标目录重叠时，标为家族归属歧义并阻止升版；不截掉后者的源名后缀，也不凭修改时间猜测。只有一个 `A-R1.prt` 的情况仍正常按其完整基本名处理。
- 家族归属检查仅用于升版；非升版的两个原名不同且最终路径不同的 PRT 仍可正常导出。
- 检查后源/目标历史或目标身份改变，受影响项要求重新检查；手动输入仍保留。不会静默变成更高版或覆盖预检查时未选定的目标。
- 开始前发现变化则尚未启动 Worker；批次开始后的单项变化以失败记录，其他已冻结且无冲突的项可继续，不逐文件弹窗。
- Worker 返回后、每项正式发布前，GUI 还要重新比较该项冻结的家族 CatalogSnapshot；即使预定目标仍不存在，其他历史 R 版新增、删除或出现异常别名也使该项失败。不能只检查最终目标路径。只比较相关家族，其他图纸和当前自有临时文件不应误触发变化。
- 目录扫描、输入有效性、最终路径及发布条件都保留稳定错误代码和可本地化原因。

## 7. 发布安全与双 Worker 边界

GUI 将每项最终源/目标/临时路径解析并冻结后交给 Worker，Worker 不选择版次、不重新命名正式输出，只写唯一临时 PDF。

协议 2 的跳过判定在 GUI 规划阶段完成，已跳过项不发往 Worker。对于发给 Worker 的 Skip 项，期望目标原本不存在；若 Worker 阶段已出现目标，记录“目标已变化，未执行”的失败，不能沿用旧 BatchStateMachine 的 SkippedExisting 分支。两代 Worker 共用的状态机必须同步修订。

正式发布明确区分“只能新增”和“覆盖预检查选定的现有目标”：

- 临时 PDF 完整通过现有文件头、页数及已有结构规则后才发布；真正视觉一致性仍要人工/渲染验证。
- 新增采用禁止覆盖的文件操作；即使目标在最后一瞬间出现，也不能将它变成覆盖。
- 覆盖保存目标身份/内容指纹，开始前及最终替换前校验；备份在正式结果验证通过前保留。发现身份变化、共享冲突或校验失败时保留文件与证据，不假报覆盖成功。
- 在普通本地文件系统上实现并验证保护；不宣称对任意网络盘或非协作外部写入拥有跨进程事务隔离。若替换期间检测到竞争，保留备份且不删除/强行恢复覆盖第三方新文件；状态明确要求人工处理。
- 任何失败都不能把残缺临时文件作为官方输出；清理只处理本次拥有的临时文件，不能按模糊文件名扫删。
- 原有 SafeOutputPublisher 的“目标此刻存在就覆盖”不足以满足新规则，必须引入冻结发布意图与期望状态；不能只修改 GUI 文案。

协议设计者决定：提升到协议 2，增加明确的分组输出/升版枚举语义，两代 Worker 与 GUI 同包更新；逐项绝对目标路径继续是执行依据，不让旧 `BesideSource` 枚举冒充自定义分组。旧版/未知版协议明确拒绝，不混用旧 Worker。发布意图与目标快照由 GUI 端冻结计划持有，Worker 不承担正式发布。

协议 2 的 FileResult 同时携带稳定 `ReasonCode`、`ReasonArguments` 和独立 `TechnicalDetails`。Worker/Core 使用原因代码表达目标变化、模型缺失、视图更新失败等事实，App 按当前语言渲染；禁止解析中文 Message 判断原因。现有 Message 可保留为诊断兼容字段，不作为显示语言或业务判断依据。未知原因代码用本地化通用说明并保留技术详情，不能凭原因字符串将 Failed 变为 Success。

## 8. 语言、菜单和错误

默认简体中文，支持 English。产品拥有的菜单、按钮、状态、解释、校验消息、汇总和说明均通过稳定键本地化；内部枚举和协议保持稳定。第三方/NX 原始异常可在技术详情保留原文，主提示提供所选语言的说明。切换立即作用于当前视图，不清空编辑值。

菜单：

- 文件：选择扫描目录、添加 PRT（切到手动模式并展开）、打开选中项所在目录、退出（沿用安全停止）。
- 视图：设置区展开/折叠、问题筛选、文件名搜索、恢复默认布局。
- 选项：语言、主题与皮肤、界面字号。
- 帮助：本地使用说明、版次规则、打开日志、关于。无联网更新或远程入口。

目录打开必须针对当前选中项；多项/多目录提供明确选择，不误开第一条结果。没有结果或目录不存在时说明原因。

## 9. 主题与图片

### 9.1 主题预设与操作

保留纯色主题：云白、石墨黑、湖蓝、松绿、暖砂；设计者选择首启云白。主题覆盖菜单、按钮、输入框、表格、选中态、弹窗和工具提示，采用协调色板；不能只换背景图。

外观面板提供纯色、预置角色、导入图片。支持图片缩放/位置、背景显现程度（透明度）、模糊、雾化色层与渐变。明确滑块高低方向：图片显现程度 0 为隐藏、100 为完全显示；模糊/雾化/渐变 0 为无效果。文字和编辑区域不跟随整窗淡出。

实时预览、应用、取消、恢复当前预设。取消恢复打开面板前外观；仅应用后保存。每个预设保留独立调整值，恢复预设不改文件和版次。导入静态 PNG/JPEG，读取像素和方向后生成工作副本，不修改用户原图。处理失败保留当前主题；加载/缓存/缩放不阻塞主窗口，不在表格每次重绘时重新模糊原图。

设计者给导入上限：32 MiB、4096 万像素；超过时显示限制，不静默导入失败。预置图优先 2560×1440 或相同比例高清图，随窗口裁切定位。

## 10. 状态与配置

沿用现有 NX 配置，不重写其 schema 或失效恢复行为。设计者选择另存 `ui-settings.json`，保存语言、主题 ID/参数、字号、窗口/分隔/列宽；采用同目录临时写入和安全替换。未知 schema、损坏文件、缺失图片或失效屏幕位置恢复云白/默认布局并给一次可操作提示，不阻止导出。

输入清单、源目录组、目标映射、手动版次和预检查事实只保存在当前会话；不额外落盘业务路径。任务自身必要的 job/result 仍按既有私有运行目录规则保存。

运行中冻结输入、输出、策略与版次；语言和皮肤可以调整，但不能改变冻结计划。当前文件关闭/取消沿用安全停止，不强杀 NX。不把耗时不确定的 NX 步骤伪装成精确百分比；可显示已完成文件数/总数。

## 11. 实施责任边界

- Core：分组映射、版本解析/枚举、计划和冲突、不可变发布意图及安全发布。
- Contracts：协议 2 与枚举语义，严格拒绝未知/旧协议；不增加 NX 引用。
- App 控制器：会话编辑、计划失效/刷新/冻结、两代 Worker 调度、状态翻译和逐项结果。
- App UI：标准 DataGridView、可拖分隔、折叠区、目录映射、详情、菜单、皮肤设置；局部自绘负责背景与外观，不接管表格业务规则。
- 素材/打包：四套真实素材、来源清单、包内相对路径与完整性检查。

准确接口和任务顺序在实施计划给出。开发者可决定内部类拆分、控件细节、缓存实现和具体色值，但不能缩减四套皮肤、任意指定版次、原因展示或安全边界。
