# v2.0.1 双版本人工验收清单

本清单是操作要求，不是通过证据。GUI、窗口、截图、Windows 缩放和物理断网均由用户本人操作。不得据自动化报告勾选人工 PASS。

2026-09-19 维护者已手动试用并确认问题修复、授权发布；未提供本清单各项独立记录，因此以下矩阵继续用于后续验收，不预先全选 PASS。

## 1. 目的、包和前置条件

目的：验证一个便携 GUI 的双版本选择、真实导出、布局、离线行为，以及旧版图纸在 NX 2506 中的标注差异。

- 使用 v2.0.1 Release 的 ZIP、SHA256SUMS.txt 和 manifest.sha256。先比较 ZIP 哈希，解压到全新中文/空格目录（如自行选择的 `测试包 双版本`），保留全部目录层级。勿把新 Worker 混入旧包。
- 本机安装的三组件元组必须与报告一致；不要升级 NX 或调整系统配置来绕过失败。关闭正在编辑的样例；不用其他有未保存工作的 NX 窗口测试。
- 使用制图及关联模型的隔离副本，同目录保留原名。原始样例只读取；不得保存、覆盖、移动或重命名。所有输出选新建统一目录；默认跳过已有 PDF。
- 自动验证曾观察到旧版图纸在 NX 2506 中的标注位置/角度显示差异；维护者随后反馈手动试用已经修复。新图纸或新环境仍按第 2 节核对，不能把一次反馈外推至所有图纸。
- 证据放到独立文件夹，例如 `验收证据/日期/版本/缩放/`；私有截图、PRT、PDF、日志和哈希不得加入 Git。

准备以下 PowerShell 变量（由用户填入实际路径）：

```powershell
$zip = '候选 ZIP 的完整路径'
$drawing = '隔离副本制图 PRT 的完整路径'
$model = '隔离副本关联模型 PRT 的完整路径'
$evidence = '本轮新建证据目录的完整路径'
New-Item -ItemType Directory -Path $evidence
Get-FileHash -LiteralPath $zip -Algorithm SHA256 | Export-Clixml (Join-Path $evidence 'zip-hash.xml')
Get-FileHash -LiteralPath $drawing,$model -Algorithm SHA256 | Export-Clixml (Join-Path $evidence 'before.xml')
```

预期：ZIP 哈希与报告相同；两份 PRT 可读。每次真实导出都重新保存本轮 before/after，不借用上一轮哈希。

## 2. 优先确认 NX 2506 原生图纸行为

1. 本人启动 NX 2506，打开隔离副本；不保存。预期：关联模型齐全，无加载/更新错误。若报错，停止，不通过修改原件规避。
2. 打开本工具导出的有效图纸页，使用“适合窗口”查看整页，再放大有差异的尺寸区域。截图完整 NX 窗口（包含标题、版本信息和该页），另存该尺寸区域清晰截图；记录 Windows 缩放、NX 图纸页名称和视图缩放值，仅存私有证据。
3. 本人使用 NX 2506 自带 PDF 导出/打印至新的文件，白底黑线、原始纸张、不追加。预期：能确定原生 PDF 与本工具 PDF 是否一致。对两者均截图整页（适合页面）和同一标注区域（200%）；不得覆盖原参考 PDF。
4. 同样用 NX 10 打开另一组副本并导出至新路径，对照参考 PDF。记录差异出现于屏幕、原生 PDF、工具 PDF 中哪一层。关闭时不保存。
5. 提供一组 NX 2506 原生制图及完整关联模型用于后续验证（可脱敏），单独记录其来源版本；当前旧版样例的结果不代表该项已完成。

停止条件：标注语义、尺寸值、角度、关联关系或符号有未解释差异；依赖/更新失败；任何保存提示或源哈希变化。保存证据后停止该项，不自行改成 PASS。

各档使用显示器原生分辨率；记录分辨率、多屏布局、主屏和 Windows 缩放。由本人在 Windows 显示设置切换缩放；如 Windows 要求注销，先安全关闭测试程序再注销。每档重新启动候选 GUI，勿依赖跨屏拖动代替三档启动测试。

每档步骤与预期：

1. 双击解压后的 GUI。预期：显示两个正确版本、路径、NXOpen 和 UF 版本；无有效保存项时开始按钮禁用，必须选择。已有有效保存项时保持上次选择。截图包含完整主窗口标题栏、环境区和所有边缘。
2. 分别选择 NX 10、NX 2506，关闭并重启。预期：选项被记住，双候选仍可切换；手动选择另一个有效根目录后也保留切换入口。不要删除用户原配置来强制测试；无保存项场景可使用另一测试账户。
3. 手动选择明显不是 NX 的空测试目录。预期：具体中文提示，原有效选择与设置保持。截图完整环境区与提示。
4. 扫描副本目录，默认不递归，再勾选递归；子目录准备独立完整样例副本。预期：递归只在主动启用时包含子目录。
5. 切换手动多选，选制图与模型。预期：完整输入列表、无重复，模式不适用项隐藏/禁用。截图全窗口。
6. 选择一个新建的长中文/空格统一输出目录，执行预检查。预期：完整基本名不丢失、默认跳过、冲突明确且阻止运行。截图预检查列表与输出区。
7. 分别运行两版本，每次使用新的输出目录及新哈希文件。预期：检测/切换/开始按钮在运行时禁用，进度和结果可读；模型跳过，不把失败当模板页。截取运行中的完整主窗口，再截终态完整窗口。
8. 在两个副本文件批次中点击取消。预期：当前文件完成后停止，后续显示取消，正式 PDF 完整。不要通过强制关闭进程验证取消。
9. 调整窗口到最小尺寸和较大尺寸，逐次按 Tab。预期：无裁切重叠，所有按钮可访问，中文和长路径可查看，Tab 顺序合理。截图出现问题的完整窗口。

文件建议：`100-nx10-selected.png`、`100-nx2506-selected.png`、`100-nx10-running.png` 等；125/150% 分别命名。截图不能只截局部来掩盖边缘裁切。

## 4. 每次导出后的证据

```powershell
Get-FileHash -LiteralPath $drawing,$model -Algorithm SHA256 | Export-Clixml (Join-Path $evidence 'after.xml')
$before = Import-Clixml (Join-Path $evidence 'before.xml')
$after = Import-Clixml (Join-Path $evidence 'after.xml')
Compare-Object ($before | Sort-Object Path) ($after | Sort-Object Path) -Property Path,Hash
```

预期：Compare-Object 没有任何输出。保存该次 `%LocalAppData%\NxDrawingPdfExporter\runs\<runId>` 中 job.json、result.json、run.log 和 stdout/stderr；这些仅作为本地私有证据。另存实际 PDF 的 SHA-256。用 PDF 查看器逐页查看：页数等于导出页数，图幅/页序正确，白底黑线，无水印/截断/残缺，尺寸标注与对应 NX 版本原生显示一致。自动 PDF 结构检查不替代此项。

## 5. 物理断网与其他机器

1. 先核对同一 ZIP 哈希，在仓库外全新目录解压；使用新的副本和输出目录，保存 before 哈希。
2. 本人拔网线、关闭 Wi-Fi 或禁用相应网卡，确认实际断网并截图 Windows 网络状态；助手不操作网卡。
3. 依次运行两个已安装版本，自动发现、选择、导出并逐页检查。预期：无下载、安装、更新或意外联网提示。若许可证本身必须联网且因此无法取得 Session，记录环境限制和真实错误，不能记为离线 PASS。
4. 保存完整 GUI 终态、日志、PDF、after 哈希和断网证据，然后本人恢复网络。
5. 同事电脑重复本流程，尤其记录非本机安装路径、实际三组件版本和自动发现来源。若仅手选可用，记录“手选通过、自动发现失败”，不可混为自动发现通过。

任何错误版本启动、源哈希变化、正式输出残缺、意外联网/安装提示、控件裁切或不可解释尺寸变化都停止该项。保留首次失败，勿覆盖或反复试到成功后删除失败记录。
